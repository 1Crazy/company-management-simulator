## Context

当前项目已经具备完整的经营回合、事件、结算、趋势图和本地存档能力，但游戏主界面仍然保留了较强的“后台表单页”气质。最近几轮迭代虽然已经加入帮助面板、策略模板和更紧凑的趋势查看方式，但桌面端 `Decision Room` 仍然容易在多列布局中失去主导宽度，导致输入卡被压缩；与此同时，现有偏冷的浅蓝控制室配色更像企业 BI 面板，而不像一款让人愿意持续推演的策略经营游戏。

此外，当前应用仍然通过内存态 `screen` 字段在开局页和游戏页之间切换，没有正式的路由层，也没有针对不同界面设置中文页面标题。这会让地址栏、页面语义和返回行为都不够清晰，也让顶部栏、帮助面板和区域标题中的英文标签显得突兀。

这次变更的利益相关区域主要集中在：

- `src/components/game/*`：游戏主界面的主布局、经营方案区、趋势区和反馈区
- `src/components/common/AppTopBar.vue`：顶部状态和主操作层级
- `src/main.ts` / `src/router/*`：页面入口、主流程路由和页面标题
- `src/style.css`：全局视觉 token、按钮、卡片和状态类
- `src/ui/playbook.ts`：策略模板、帮助文案和工作台辅助信息

约束条件：

- 不改变现有经营规则、数据模型和本地存档结构
- 不引入后端、AI 能力或额外 UI 组件库
- 继续维持 TailwindCSS + Vue SFC 的分层结构，避免单文件膨胀
- 保持桌面端高信息密度，同时不牺牲移动端可访问性

## Goals / Non-Goals

**Goals:**

- 为桌面端经营方案区提供稳定且充足的主操作宽度
- 将经营字段按业务语义重新分组，并为高频调整提供更顺手的交互
- 将预提交摘要前置为真正的决策辅助层，而不是附属信息块
- 把趋势区控制为按需查看的焦点区域，减少不必要的纵向滚动
- 将视觉系统切换为更有策略游戏氛围的暖石 + 深炭 + 金色强调配色
- 引入 `vue-router` 管理开局页与经营主界面的主流程页面
- 将核心界面文案调整为中文优先，并提供中文页面标题

**Non-Goals:**

- 不重写经营公式、事件系统或数值平衡
- 不新增新场景、新存档格式或联网能力
- 不在本次变更中引入复杂动画、3D 风格或重度游戏化特效
- 不把整体界面改为全暗色主题
- 不把当前应用扩展为复杂的多层嵌套路由站点

## Decisions

### 1. 将桌面端游戏主界面调整为“主操作区 + 侧边控制塔”非对称布局

**Decision**

桌面端主界面不再维持三列近似平分的网格，而是改为：

- 左侧主操作区：经营方案工作台 + 财务反馈
- 右侧侧边控制塔：目标、里程碑、存档和最近回合

**Rationale**

用户当前最核心的问题不是信息不够，而是 `Decision Room` 没有拿到足够横向宽度。只要它继续和报表、控制塔做三列竞争，输入控件就会被压缩。把主操作和信息侧栏明确分区，能同时提升宽度和浏览节奏。

**Alternatives considered**

- 保留三列，但继续微调列宽比例：仍然难以保证经营方案区稳定获宽
- 把所有区域改成单列纵向：会牺牲桌面端的高信息密度优势

### 2. 将经营方案区改为“模板 -> 摘要 -> 分组输入”的工作台顺序

**Decision**

经营方案区内部采用三层结构：

- 上层：策略模板 / 快捷预案
- 中层：横向预提交摘要和风险提示
- 下层：按业务语义分组的经营字段

字段分组以“市场、生产、组织、资金”为主，而不是平铺成同质列表。

**Rationale**

玩家需要先形成策略方向，再确认风险，再做逐项微调。现有平铺输入更像数据录入，不像操盘。通过把策略模板和摘要前置，用户能在更短路径内完成“先判断、后录入”的闭环。

**Alternatives considered**

- 保留平铺输入，只精简字段卡文案：能缩短高度，但不能改变交互心智
- 将摘要固定到右侧吸附栏：会反过来再次挤压输入区域

### 3. 对高频字段保留数字输入，同时增加快捷步进或快捷档位

**Decision**

价格、产量、预算等高频字段继续保留数字输入作为主编辑方式，同时补充快捷步进或预置调整档位；字段解释从卡片常驻说明改为分组说明、帮助抽屉或精简辅助文案。

**Rationale**

纯输入框的成本太高，纯滑杆又不适合精确经营数字。混合式控件更符合这种经营模拟的频繁微调场景。

**Alternatives considered**

- 全量改为滑杆：精度不够，移动端也会更难控制
- 只保留输入框：交互成本过高，缺少“试策略”的速度感

### 4. 趋势区继续使用焦点式标签切换，不默认全量展开

**Decision**

趋势区保持单图主视图，通过标签切换财务、现金和组织状态；不恢复为同时展开多张图的长页面。

**Rationale**

用户明确指出页面过长不利于查看。趋势信息属于辅助分析，不应该和本回合操作竞争首屏空间。

**Alternatives considered**

- 折叠面板式多图区：信息仍会持续增加纵向高度
- 保留全部展开：继续放大滚动问题

### 5. 将视觉系统改为更有策略经营氛围的暖石 + 深炭 + 金色强调

**Decision**

从当前偏冷的浅蓝控制台体系，切换为：

- 背景：暖石 / 米白中性底
- 标题与高权重文本：深炭 / 黑棕
- 主操作 CTA：金色 / 琥珀金
- 数据辅助与图表冷色：受控蓝色或青色
- 成功 / 风险 / 失败状态：独立绿色、琥珀色、玫瑰色

**Rationale**

要解决“不想玩”的问题，首先要让界面摆脱普通后台感。暖石底和深炭文字能带来更强的策略盘面质感，金色 CTA 能强化“落子”和“锁定回合”的动作感。

**Alternatives considered**

- 继续沿用浅蓝 + 琥珀体系：信息清晰，但游戏驱动力不足
- 直接转向霓虹暗黑风：情绪足够强，但会破坏长期阅读和表单可读性

### 6. 以 `vue-router` 替代内存态页面切换，并同步中文页面标题

**Decision**

引入 `vue-router`，将主流程收敛为最小两条主路由：

- `/`：开局面板
- `/game`：经营主界面

页面标题随路由和局面状态同步为中文，例如“公司经营模拟器”和“经营中 - 公司名”。

**Rationale**

虽然当前页面数量不多，但开局页和经营页已经形成明确的页面边界。继续依赖内存态切屏，会让地址栏、页面标题和返回行为都不稳定。既然用户已经明确问到 `vue-router`，就应把路由提升为正式结构，而不是继续把它当可有可无的实现细节。

**Alternatives considered**

- 继续使用 `screen` 状态切屏：实现简单，但页面边界和标题管理都不清晰
- 一次性扩展为更多嵌套路由：当前收益不足，复杂度过高

### 7. 将界面文案调整为中文优先，只在必要场景保留英文

**Decision**

顶部栏、区域标题、帮助抽屉、趋势标签和主要操作全部改为中文优先表达；仅在库名、技术名词或必须保留的标识中保留英文。

**Rationale**

现有中文主体已经成立，但局部英文标签会打断沉浸感，也让风格显得不统一。用户已经明确要求“尽量使用中文”，因此这次应把中文化提升为统一策略，而不是零散替换几个标题。

**Alternatives considered**

- 保留双语混用：对开发者友好，但对玩家沉浸感不友好
- 强行清除所有英文：会让少数技术名词表达变得生硬

## Risks / Trade-offs

- [Risk] 主操作区变宽后，右侧控制塔可能显得信息更密 → Mitigation：控制塔维持固定窄侧栏角色，只承载目标、存档和近几回合关键信息
- [Risk] 色系切换后已有状态类可能失去层级统一 → Mitigation：统一在 `src/style.css` 中重建 token，不在组件里零散写新颜色
- [Risk] 分组式输入增加结构复杂度 → Mitigation：通过新增小组件和 `playbook` 配置维持低耦合
- [Risk] 为了缩短页面而过度压缩信息 → Mitigation：把说明迁移到帮助抽屉和分组标题，不删除关键反馈
- [Risk] 引入 `vue-router` 后，当前 start / restore / back-to-menu 流程可能出现状态与 URL 不一致 → Mitigation：先保持 session 状态来源不变，只把页面切换改为路由驱动
- [Risk] 中文化过程中残留少量英文标签 → Mitigation：集中扫描 `src/components` 和页面标题入口，统一替换

## Migration Plan

1. 先更新 OpenSpec 规格，明确工作台布局、字段分组和视觉系统变更
2. 重构 `GameScreen` 主布局，给经营方案区预留足够主宽度
3. 重构 `DecisionPanel` 与字段卡，落地分组与快捷交互
4. 更新趋势区与顶部栏的视觉层级和信息优先级
5. 引入 `vue-router`，替换 `screen` 驱动的页面切换并接入中文页面标题
6. 统一调整 `src/style.css` 中的配色 token 与组件公共类，并扫描英文界面文案
7. 跑桌面端截图验证、单元测试和构建验证

回滚方式：

- 若新布局导致明显可用性回退，可先回退 `GameScreen` 与 `DecisionPanel` 布局改动
- 若新配色影响可读性，可仅回退 `src/style.css` 视觉 token，而保留交互层重构
